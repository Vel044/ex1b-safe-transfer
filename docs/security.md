# 安全设计与验证范围

## 信任和身份

客户端仅信任用户选定的实验CA，并验证TLS服务器名称及证书链。服务端要求CA签发的客户端证书，再以DER证书SHA-256指纹查询启用账户。证书CN和HELLO中的任意用户名都不作为账户授权依据。

生成证书使用RSA 3072及SHA-256，CA含CA约束，服务器含serverAuth和SAN，客户端含clientAuth。CA私钥不挂载到强化隔离服务容器。客户端可将身份导入系统钥匙串，配置保存持久引用；未保存时密码仅存在内存。应用不安装全局根证书。

实验未部署OCSP或CRL；客户端身份撤销通过禁用账户及精确指纹登记完成。实验CA及服务器私钥泄露需要重新生成和分发，不应把当前实验凭据用于真实业务。

## 文件边界

服务器的每次路径操作都从账户根目录描述符出发，拒绝绝对路径、点段、反斜杠及空段。逐层使用O_DIRECTORY、O_NOFOLLOW和dir_fd打开；只传输普通文件，不跟随符号链接，也拒绝已有多硬链接的可下载文件。下载到Mac时同样使用openat、O_NOFOLLOW及fstatat检查。

上传临时文件及数据库位于private目录，业务LIST不可访问。正式文件通过linkat提交，已有名称必然导致失败；只对上次提交留下的同inode链接执行恢复清理。客户端App Sandbox仅授予网络连接及用户选择文件的权限，恢复目录访问依靠安全作用域书签。

## 资源预算

| 项目 | 默认值 |
|---|---|
| 全局连接 / 单IP / 单账户 | 32 / 8 / 2，包括TLS握手中连接 |
| 活动文件 | 每账户4 |
| 单连接未完成请求 | 16 |
| 报文元数据 / 文件块 | 各64KiB |
| 握手 / 半包 / 空闲 | 5秒 / 15秒 / 45秒 |
| 管理请求频率 | 每连接每秒30次；DATA、READ、ACK、PING另有协议约束 |
| 单文件 / 账户配额 | 1GiB / 2GiB，未完成上传也预留 |
| 目录深度 / 枚举条目 | 32层 / 10000 |
| 账户历史任务 | 10000条，需要管理员归档后继续扩展 |
| SQLite审计 / 轮转日志 | 最近5000条 / 1MiB文件及3份备份 |

共享令牌桶以账户为粒度，不按连接重新分配预算；上传及下载共用预算。令牌容量64KiB，允许一个数据块的短时突发。0 表示关闭账户应用层限速；非零上限最小为 64KiB/s。限速等待发生在独立请求任务，读取循环仍可接收心跳。内存有界，但不保证互联网规模DDoS防护；上游带宽耗尽需要网络侧措施。

## 数据库及部署

SQLite查询统一使用参数绑定，事务使用WAL和FULL同步。上传配额以BEGIN IMMEDIATE事务预留，防止并发超卖。业务不接收SQL片段、脚本或命令。

强化隔离配置 compose.hardened.yaml 的容器以UID 10001运行，根文件系统只读，cap_drop=ALL，no-new-privileges，内存256MiB、CPU 1、进程64、文件描述符1024。只挂载项目数据及必要服务器证书，端口仅发布在127.0.0.1。初始化容器短时以root设置这两个项目目录的权限，不运行网络服务，不接触CA私钥或客户端私钥。

这些措施减少误操作及服务进程被控制后的宿主机暴露范围，不意味着容器等价于完全隔离的安全边界。证书、路径边界、输入限制及容器权限必须共同生效。

## 账户读写权限

证书指纹绑定账户，账户 access 为 r 或 rw；服务端对每条请求检查权限。r 禁止上传、建目录、复制、删除及恢复上传。DELETE 按账户根目录描述符访问，不跟随符号链接，拒绝仍有未结束任务的路径。COPY 先预留配额、验证源文件与副本哈希，再禁止覆盖地提交目标；目录批量操作不提供整体原子性。

## 默认 SSH 与强化隔离模式

compose.yaml 默认提供本机 2222 端口的公钥 SSH，禁止 root 与密码登录。文件服务仍以 UID 10001 运行，SSH 启动进程以 root 运行，容器文件系统及 VS Code 主目录可写，宿主项目只读映射到 /workspace。compose.ssh.yaml 保留为等价兼容入口。重启默认配置不会关闭 SSH。

compose.hardened.yaml 为可选的无 SSH 强化隔离配置：只读根文件系统、cap_drop=ALL、no-new-privileges，不挂载宿主项目。报告应注明实际使用的模式，不能用默认 SSH 模式证明强化隔离属性。切换需重建容器，不删除服务数据。

私钥不复制到容器，runtime/ssh 下的主机密钥不提交源码。
